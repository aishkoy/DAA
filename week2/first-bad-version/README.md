First Bad Version

1. Problem
Есть версии программы 1, 2, ..., n. Начиная с какой-то сломанной версии k, все версии от k до n тоже сломаны. Есть функция isBadVersion(version). Нужно найти первую сломанную версию.

2. Approach
1) Как в бинарном поиске, заводим left = 1, right = n и middle - середину между ними.
2) Цикл while идёт, пока left != right.
3) В цикле проверяем, сломана ли версия middle.
4) Если сломана, то либо middle и есть первая сломанная, либо первая сломанная меньше неё, поэтому right = middle.
5) Если middle рабочая, то первая сломанная точно больше, поэтому left = middle + 1.
6) Когда left == right, остался один элемент, это и есть первая сломанная версия.

В Java-файле isBadVersion подменён методом класса, который сравнивает версию с полем firstBad, потому что на LeetCode эту функцию дают готовой.

Tracing
n = 5, первая сломанная версия 4
Итерация 1: left = 1, right = 5, middle = 3, isBadVersion(3) = false, left = 4.
Итерация 2: left = 4, right = 5, middle = 4, isBadVersion(4) = true, right = 4.
left == right == 4, ответ 4.

Challenges
Середина считается как left + (right - left) / 2, а не (left + right) / 2, иначе при n около 2^31 - 1 сумма переполняет int.

3. Time Complexity
Time Complexity: O(log n)

Каждая итерация делит область поиска пополам. Пусть k - число итераций, n - размер области поиска:
после 1 итерации n/2
после 2 итераций n/(2^2)
после k итераций n/(2^k)
Поиск закончится, когда n/(2^k) = 1, то есть n = 2^k и k = log2 n.

4. Space Complexity
Space Complexity: O(1)

Нужны только 3 переменные: left, right и middle.

5. Reflection / Improvement
Бинарный поиск - оптимальный алгоритм для этой задачи. Важная деталь реализации - как считать середину. n может быть до 2^31 - 1 = 2 147 483 647. Если left и right близки к этой границе, то left + right больше максимального int, и в Java получится отрицательное число. В left + (right - left) / 2 такого не будет, потому что right - left всегда помещается в int. В main это проверяется на n = 2126753390.
