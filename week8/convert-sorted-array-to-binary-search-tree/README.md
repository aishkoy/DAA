Convert Sorted Array to Binary Search Tree

1. Problem
Дан массив nums, отсортированный по возрастанию. Нужно построить из него сбалансированное дерево поиска (BST): глубины левого и правого поддерева любого узла отличаются не больше чем на 1.

2. Approach
1) Корнем делаем средний элемент массива. Всё, что левее, меньше него и уходит в левое поддерево, а всё, что правее, - в правое.
2) Половины получаются одинакового размера (плюс-минус 1), поэтому дерево сбалансированное.
3) Рекурсивно повторяем то же самое для левой и правой половины.
4) Массив не копируется, во вспомогательную функцию build передаются границы куска left и right. Если left > right, кусок пустой и возвращаем null.

Tracing
nums = [-10, -3, 0, 5, 9]
build(0, 4): mid = 2, корень 0.
build(0, 1): mid = 0, узел -10, левый ребёнок 0.
build(1, 1): mid = 1, узел -3, правый ребёнок -10.
build(3, 4): mid = 3, узел 5, правый ребёнок 0.
build(4, 4): mid = 4, узел 9, правый ребёнок 5.
Результат: [0, -10, 5, null, -3, null, 9].

Challenges
Ответ не единственный: при чётной длине куска можно брать и левую, и правую середину, LeetCode принимает оба варианта. Середина считается как left + (right - left) / 2.

3. Time Complexity
Time Complexity: O(n)

Каждый элемент становится узлом ровно один раз, на каждый вызов уходит O(1) работы.

4. Space Complexity
Space Complexity: O(log n), не считая самого дерева

Дерево сбалансированное, поэтому глубина рекурсии O(log n). Само дерево занимает O(n), но это ответ.

5. Reflection / Improvement
Это оптимальное решение: быстрее O(n) нельзя, потому что нужно создать n узлов. Если бы половины копировались через Arrays.copyOfRange, сложность выросла бы до O(n log n), поэтому передаются индексы.
