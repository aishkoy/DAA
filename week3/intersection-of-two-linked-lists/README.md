Intersection of Two Linked Lists

1. Problem
Два односвязных списка в какой-то момент сливаются в один. Нужно найти первый общий узел или вернуть null, если они не пересекаются.

2. Approach
В файле два решения.

Первое, getIntersectionNode:
1) Заводим HashSet посещённых узлов списка A.
2) Проходим список A и добавляем все его узлы в множество.
3) Проходим список B и возвращаем первый узел, который уже есть в множестве.
4) Если такого нет, возвращаем null.

Второе, getIntersectionNodeTwoPointers (придумала не сама, но разобралась):
Два указателя идут по спискам, и когда один доходит до конца, он переходит на начало другого списка. Каждый проходит len(A) + len(B) шагов, поэтому на втором круге они встречаются в точке пересечения, или оба оказываются в null, если пересечения нет.

Tracing
A = 4 -> 1 -> 8 -> 4 -> 5, B = 5 -> 6 -> 1 -> 8 -> 4 -> 5, общая часть начинается с узла 8.
Первое решение: в множестве все узлы A. Идём по B: 5 нет, 6 нет, 1 нет (это другой узел с тем же значением), 8 есть, ответ 8.

Challenges
Сравниваются узлы, а не значения: в примере у обоих списков есть узел со значением 1, но это разные узлы.

3. Time Complexity
Time Complexity: O(n + m)

Худший случай - списки не пересекаются или пересекаются только на последнем узле, тогда оба списка проходятся полностью. У второго решения тоже O(n + m).

4. Space Complexity
Space Complexity: O(n) для первого решения, O(1) для второго

В первом решении в множестве хранятся все узлы списка A, во втором только два указателя.

5. Reflection / Improvement
Второе решение лучше по памяти. Самое очевидное - пустить два указателя до точки пересечения - не работает, потому что до пересечения списки могут быть разной длины. Переход на начало другого списка выравнивает длину пути для обоих указателей.
