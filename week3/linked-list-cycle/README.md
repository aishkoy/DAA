Linked List Cycle

1. Problem
Дана голова односвязного списка. Нужно определить, есть ли в нём цикл, то есть указывает ли последний узел на какой-то узел этого же списка.

2. Approach
1) Заводим HashSet узлов, в которых уже были.
2) Если текущий узел уже есть в множестве, возвращаем true, это цикл.
3) Иначе добавляем узел в множество и рекурсивно запускаем то же самое для head.next.
4) Если дошли до null, цикла нет, возвращаем false.

Tracing
3 -> 2 -> 0 -> -4, и -4 указывает обратно на 2
Узел 3: множество пустое, добавляем.
Узел 2: добавляем.
Узел 0: добавляем.
Узел -4: добавляем.
Узел 2: уже есть в множестве, возвращаем true.

Challenges
В множестве хранятся сами узлы, а не значения: значения в списке могут повторяться и без цикла.

3. Time Complexity
Time Complexity: O(n)

В худшем случае последний узел указывает сам на себя, и проходим весь список. Проверка contains в HashSet в среднем O(1). Если бы узлы хранились в списке, а не в множестве, сложность была бы O(n^2), потому что проверка, есть ли элемент в списке, линейная.

4. Space Complexity
Space Complexity: O(n)

В множестве может оказаться весь список, и глубина рекурсии тоже до n.

5. Reflection / Improvement
По времени лучше O(n) не сделать, но есть решение с O(1) памяти - алгоритм Флойда (черепаха и заяц):
1) Заводим два указателя: медленный на текущем узле и быстрый через один узел.
2) Если у быстрого нет следующего узла, цикла нет.
3) Пока есть, двигаем медленный на 1 узел, а быстрый на 2.
4) Если цикл есть, быстрый указатель догонит медленный.
